# Capture 25: preserve motion with the opaque depth boundary

Capture 25 was generated by 54e08263 (640x360 -> 1280x720, CUSA00004 01.00).
The reported face blur is still present. The capture-23 spatial recovery was
not a demonstrated solution for this scene and has been withdrawn.

## What is measured

The pinned SDK replay reproduces the phone's f001 output with RGB MAE
0.02629485 in 8-bit units (face crop x604..656/y308..380: 0.06036325).
The distortion is already present in the SDK history before RCAS. Resetting
the history loses detail; changing the jitter sign does not solve it. Neither
is a production change.

The scene is effectively stationary. Across the face, the captured input moves
about (-0.90,+0.31) input pixels between frames, consistent with the recorded
Halton delta (-0.953125,+0.33333334). Most face motion output is zero. At input
(315,170), f001 has a valid object tag with depth 0.029523898, while the saved
scene depth is 0.03157604. The strict depth test rejects this tag correctly.
The discarded vector is only (-0.005438626,+0.000090525) pixels, so the previous
0.15-pixel recovery floor cannot address this case.

This establishes a mismatch of the resources consumed by reconstruction. The
capture does NOT identify the exact guest draw that produced the other layer.
Do not claim that a particular skin, SSS, back-face or lighting shader has been
identified or fixed merely from this pair of frames.

## Runtime defect and correction

`SnapshotIssSceneDepth` preserved depth at the first HDR scene-lighting boundary.
`ObjectMotion::Attach` and `PrepareDraw` remained writable until AA. Consequently
later motion-enabled auxiliary passes could replace the image, resize/clear it,
and update the next frame's vertex history after the saved depth's geometry stage.
The old recovery attempted to estimate around rejected vectors instead of
preserving the original pair.

At the exact existing depth-copy boundary, seal the opaque object-motion image
AND its position history for the rest of this frame. Subsequent motion-pipeline
draws keep their Vulkan output location but bind a null/unused color attachment;
no game color/depth attachment changes. Their motion parameter is zero, so they
cannot replace the stored opaque vertex positions. Next frame releases the seal
before collecting new geometry. The compose pass and on-demand dump read the
preserved image. No extra GPU images, copies, readbacks, per-frame allocations,
or GPU finishes are introduced.

Remove spatial neighbor recovery. Keep direct history/depth/outlier rejection,
submission-owned camera snapshots, SDK flags, jitter, sharpening, Readback,
resolution patches, and UI unchanged. No game shader recompiler change occurs.

This fixes a concrete resource-lifetime defect. Full-device confirmation of
facial quality is still required; the missing pre-overwrite object map cannot
be recovered from the two existing frames and must not be invented offline.

## Continuation: stop CPU motion preparation at the same boundary

The seal previously blocked `PrepareDraw` and the motion attachment, but the
rasterizer still hashed vertex buffers, scanned/hashed indices, read bone
palettes and called `History::Moving` before reaching the blocked method.
`Moving` mutates gate occurrence/history tables, so those tables were not
actually sealed with opaque geometry. Late work could not produce useful
motion output, yet still consumed CPU time and changed bookkeeping.

`ObjectMotion::Collecting` now gates that CPU preparation and `Moving` itself.
Every draw first publishes motion parameter zero, so skipping a late pass
cannot reuse an earlier draw's motion parameter. The existing null motion
attachment, opaque depth/motion images, game draw, resource bindings and
Vulkan synchronization are preserved. No shader, jitter, sharpening, Readback
mode, resolution or FSR SDK setting changes.

The regression compiles the production inline methods with the real motion
history implementation. It exercises 1,000 late draws, frame rollover,
opaque palette changes, unmatched repeated instances and disabled collection.
Late draws must leave history statistics unchanged and cannot become a
second occurrence's history in the next frame. Structural guards also cover
neutral parameters before early-out and both expensive hash/scan entry paths.
This removes provably unused CPU work; it is not an FPS measurement or proof
that capture 25's remaining facial reconstruction is visually resolved.
